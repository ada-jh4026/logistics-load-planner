# F02 完成导入、车辆列表及路线示意 —— 验收证据

日期：2026-10-10。执行者：前端/智能体线（Claude Code）。

## 实现
- 案例选择：顶栏下拉三个样例（全部配送 / 部分配送 / 求解失败）。
- JSON 导入：`frontend/src/lib/importRequest.ts`，先 zod 校验再做引用与范围检查（重复 ID、箱件引用不存在门店、门店无箱件、时间窗颠倒、options 范围）；失败弹出逐条问题列表，不生成半截请求。导入成功后清空旧响应，页面显示「尚无方案」。CSV 留后续（卡片允许）。
- 路线示意：`frontend/src/components/RouteMap.tsx`，平面坐标 SVG，北向上，1/2/5 km 自适应网格与刻度；仓库方块、门店圆点、按路线顺序直线连线；选中车辆用钢蓝实线并在门店上标到站序号，其它车辆灰线；未配送门店红色虚线圈。页面注明「平面坐标与直线连线，仅示意配送顺序，不是道路导航」。
- 车辆列表：`frontend/src/components/VehicleRail.tsx`，每车显示站数、箱数、费用、出发/回仓时刻、里程、载重；到站顺序色块；未启用车辆显示尺寸与载重。未配送门店独立区块显示原因码中文与消息；案例摘要显示门店/箱件数、出发时刻、车速假设。
- 右栏行程表：到达、开始、时间窗、等待时长；费用按「固定费 + 单价 × 里程」展开显示，便于核对。

## 验证
- `npm run build` 通过。
- 截图：`artifacts/evidence/screenshots/F02_partial_route_map.png`（partial 样例，路线示意）。核对：S01 到达 08:10、开始 08:20（等待 10 分）、回仓 08:35、里程 10 km、费用 100 + 2 × 10 = 120 元，与 ACCEPTANCE C01 手算一致；S02 显示为未配送（BOX_TOO_LARGE），总需求 2 家门店不变。
- 导入校验手测：用 request-partial.json 导入成功；将其 boxes[0].store_id 改为 S99 后导入，页面列出「箱件 B01 引用了不存在的门店 S99」。

## 限制
- 距离与时间为模拟网络（欧氏距离 + 固定车速）；页面文案已注明。
- 页面不重算路线，所有数值来自响应 JSON。
