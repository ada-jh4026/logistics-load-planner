# F05 切换真实服务并联调 —— 验收证据

日期：2026-10-10（英国时间 18:05）。执行者：前端/智能体线（Claude Code）。后端为主线 B13（提交 a94a4f4 及之前）。

## 实现
- `frontend/src/lib/api.ts`：同源相对路径（`/api/*` 由 Vite 代理到 8000）；统一解析 CONTRACT 错误外壳为 `ApiError{status, code, message, details}`；响应用 zod 按协议校验，不符合即报 BAD_RESPONSE。`pollJob` 每 500 ms 轮询到终态，支持 AbortSignal 取消。
- `frontend/src/lib/useSolver.ts`：提交 → 轮询 → 终态回调；同一时刻只有一个任务，再次提交或切换案例会取消上一个轮询；错误保留在状态里，用户输入不丢；等待超过 75 秒提示检查服务。
- `frontend/src/lib/cases.ts`：启动时 `GET /api/health` + `GET /api/examples`，可达则把 11 个服务案例放在下拉第一组并默认选中；不可达则只剩本地样例，顶栏显示「求解服务未连接」，按钮禁用并说明原因。
- 顶栏标记：真实响应 `is_mock=false` 显示「真实求解」，不再显示「演示数据」；`data_source=synthetic` 仍显示「模拟数据」；显示 run_id 前 8 位。
- 运行中：中央显示「排队中 / 计算中，已等待 N 秒」，顶栏按钮变为「计算中 Ns，取消」，案例选择与导入禁用；新任务开始即清空旧方案；旧方案不会在新任务期间残留在右栏。
- 协议对照：真实响应顶层 11 个字段与前端 schema 完全一致（无缺失、无多余）；422/404 错误外壳与 CONTRACT 一致。

## 限制
- 中断轮询只是前端不再等待，服务端任务继续执行到完成（CONTRACT 无取消接口）。
- 请求变化（导入 JSON 后）会产生新方案，但本次未用修改后的请求做对比截图；该流程在 F07 的「指令 → 确认 → 重算 → 对比」中覆盖。
