# 核心算法实现细则
读者：B04至B12、I01/I02。实现可放在对应任务指定模块，不把UI、网络、文件读写写进纯函数。

## A1 公共约束校验
输入为原始SolveRequest和候选Result，重新算所有派生量。校验器不调用求解器来确认自己。
顺序：ID/分配完整性 → 路线与车辆唯一性 → 时间/载重 → 布局 → 卸货 → 指标。
门店分配原子化；每个箱件恰在一个路线或unassigned，空路线不出现。路线门店与箱件所属门店集合完全一致。

## A2 几何基础
旋转0尺寸=(L,W,H)，90=(W,L,H)，不允许旋转的箱件出现90即输入方案违规。
两个长方体碰撞当且仅当x/y/z三个开区间都存在严格正长度交集。仅面接触合法。
边界条件x,y,z>=0及x+L<=车长、y+W<=车宽、z+H<=车高。
z=0即落地；否则存在单个底箱，其顶面z等于该箱底面z，且完整覆盖其底面投影，底箱fragile=false。不允许浮空或跨两箱承托。
发现堆叠仅报告几何支持，不假定材质承重参数已经建模。

## A3 卸货
按路线依次处理门店，当站所有箱件必须卸完才能进入下一站。
每次在该站尚未卸箱中，按(z降序,x升序,id升序)寻找可取箱：
1. 不存在仍由它承托的其他箱；否则SUPPORT_DEPENDENCY。
2. 将该箱沿-x移出车门。扫掠空间可用x区间[0,x+L]与箱体原y/z区间；任何其他箱与这三个区间严格相交即阻挡（排除自身，接触面不算）。
3. 移除后剩余布局的承托仍成立。
可取则写一步并更新集合；全部候选都不可取则UNLOAD_BLOCKED。后站箱件不允许临时搬出。
生成卸货序列与验证外部序列分开；验证器严格执行传入步骤，检查次序和完整性。
装货指引取卸货逆序，并验证从空车起逐件沿+x放入及承托，不通过则不能宣称可执行装货。

## A4 基线greedy
门店先按最早window_end、再ID排序。枚举已有车及未使用车辆的尾部追加，在载重、总箱体积和时间窗都可行的候选里选增量成本最低者；平局选vehicle_id。
车辆/容量预筛仅是必要条件。分配结束后用公共packer生成装载，使用独立validator确认。失败整车退回unassigned，不做移单反馈修复。
这不是行业人工调度的实测替身，报告写“简单贪心基线”。

## A5 路线sequential
同样门店排序，对所有车及所有插入位置计算增量成本，选择可行最小值。可做最多2轮2-opt；每次都重新检验时间窗，不接受费用变差。
之后调用与greedy相同的packer。失败整车退回unassigned，不做跨车/路线装载反馈。保留内部失败候选，供coupled从同一初始分配开始修复。
三个方法使用相同预处理、packer、校验器及总时间预算。区别是路线策略及反馈修复。

## A6 确定性装载启发式
按目的站逆配送序、非易碎优先、体积降序、ID排序处理箱件。允许每个箱的两种水平朝向。
初始候选位置是车厢地板角及靠车头放置的对齐位置；后续候选由已放箱边界生成：x候选含0、车长-当前箱长、已放箱x+L、已放箱x-当前箱长；y含0、车宽-当前箱宽、已放箱y+W、已放箱y-当前箱宽；z含0及各已放箱顶面。
剪掉负坐标/越界，去重，过滤碰撞、承托、易碎规则。倾向后送货靠车头、低重心，按固定评分和坐标排序选择。候选数量设上限并记录；因此算法不完备，失败只表示没找到。
所有箱放完再模拟卸货。尝试最多3种稳定箱排序（默认、尺寸降序、同站易碎最后）；每次均受全局时间预算约束。不能只在末尾才检查时间。
支持ground_only调试开关只用于定位问题，正式约束和实验设定必须一致，不可悄悄切换降级。

H01 实际实现：同规格保持上述路径；存在多种长宽高时，先按逆站序尝试三种可装入构造（按站纵向分区/底面积排序、共享空间/底面积排序、共享空间/体积排序），失败再回退上述三种旧排序。站内非易碎优先，尺寸评分后按高度、ID稳定排序。分区模式每完成一站，把下一站可用车长收至该站最小x；共享模式允许符合既有单箱承托规则的跨站叠放。

异构候选另外包含已放箱左/右边对齐的x/y位置，补足不同底面尺寸的承托机会。候选坐标按优先序惰性生成，最多2000个；构造模式合并两个允许朝向后，依次按已占纵向深度、z、y、-x、朝向选取前2000个。每个放置除碰撞、承托、易碎检查，还检查沿车门进入的扫掠路径，最终仍重新生成卸货序列并独立校验。每箱和每64次位置尝试检查预算。搜索依然不完备，单箱完全承托约束未放宽。

## A7 coupled反馈循环
从sequential的原始路线候选开始，保留所有门店去向及最佳已校验结果。
每次发现失败车，packer内部已尝试不同构造/排序；对冲突门店生成跨车搬移候选，包括已有车的插入位和未用车。当前未实现相邻门店交换，不能写成已完成能力。
每个候选重新检查受影响路线时间、容量、装载、卸货；最终接受前做全量独立校验。
按(未服务门店数,未服务箱数,费用,里程,稳定ID序)字典序比较。保存最佳可行快照；允许暂存失败候选进行修复，但不得覆盖最佳快照。
候选接受要求目标分数字典序严格改善，最多max_iterations次或time_limit_ms到期。没有提升就尝试下个候选，不无限重试。停止时返回最佳已验证结果，其他门店明确unassigned。
协同回归案例至少覆盖可通过移单或换顺序修复的一例；不允许按case_id写特殊分支或预置“最优结果”。

O03/H01 实际实现：搬移按估计路线费用增量稳定排序，每个冲突门店最多评估8个候选；全量重配并独立校验，通过且目标车确实服务该门店后才可接受。此阶段限于总时限15%（最多1000ms）和剩余迭代的1/5，所有工作计入同一父预算。实验内部 `selection="first"` 保留历史首可行策略用于消融，不暴露为API方法。

剩余预算用于逐店恢复：保留所有已验证路线，未配送门店按最早截止时间/ID处理；枚举满足时间窗、载重、体积必要条件的插入位。先试费用增量最低的两辆已用车各一个位置，再试空车，再试其他车辆代表位置与剩余插入位。仅重配目标车，接受前全量独立校验且服务门店数必须增加1；不丢弃此前有效门店。仅上一轮有进展才继续下一轮；失败明确保留unassigned。该顺序优先有限预算下的覆盖率，可能增加车辆和费用，不保证费用最优。过程通过现有repair_trace记录，重新插入时source_vehicle_id=null。

## A8 时间与可复现
分阶段实现约定：B05/B09/B10先接受budget=None的可选参数，核心循环保留预算检查接入点；B11创建Budget并统一接入所有循环，此后正式solve不得传None。B05/B09完成只表示其局部能力通过，不代表全局超时控制已经实现。
使用单调时钟，预算覆盖本方法的路线构造、pack、修复及最终校验；为最终校验预留预算，例如总预算的10%。计时压力会导致边界差异，记录终止原因。确定性用稳定排序和seed；功能测试用足够预算和迭代上限，比较结果时忽略run_id与elapsed_ms。
几何校验先朴素O(n²)，标准规模达到要求再谈索引优化。
