# 接力提示词与交接格式
## 给下一位主线模型（直接复制）
你在城市配送智能配载参赛项目中接力。先读START_HERE.md、AGENTS.md、docs/playbook/STATE.md及board.json。不要重新设计整个项目。领取编号最小且依赖全部done的主线任务；如果用户指定了任务，先检查它的依赖。只读当前任务卡列出的材料。检查已有代码后按卡片实现、运行验收并保存真实证据，更新状态。示例响应不是算法成果；不得把未运行任务标done。本次完成后按HANDOFF格式报告。无需询问已在规范中写清的常规选择；发现阻塞时精确说明缺什么，并继续不依赖它的可用任务。

## 给前端同学/模型（直接复制）
请负责本项目frontend目录。先读START_HERE.md、DECISIONS.md、CONTRACT.md和F01任务卡。先使用docs/playbook/examples的JSON开发，页面明确标注演示数据，然后按F01→F02→F03→F04推进。后端完成B13后做F05真实联调。路线和箱体必须从响应读，不硬编码优化收益。不改后端、接口规范或根配置；有变更需求发交接说明，由主线同步。提交每张卡的修改文件、启动命令、验收截图和待处理问题。

## 修复失败任务（直接复制）
读取任务卡<任务ID>、STATE.md和最近的验收证据。先复现已有失败，解释根因及影响；仅修改相关模块。保留他人变更，不通过删断言或放宽约束制造通过。修复后重跑失败验收及直接受影响的回归，记录实际命令、结果与证据，再更新状态。

## 状态操作
主线把board.json中任务改为in_progress并填写owner；完工必须填写evidence中的文件路径，然后置done。前端由同学给报告、主线确认后更新。
blocked需填写blocked_reason。被阻塞的任务不使其他独立分支自动阻塞。
如果代码已有成果但board还是pending，先验收已有成果，再决定状态，避免重复开发。

## 新模型的最小上下文
必须：AGENTS + STATE + 当前卡。
按卡追加：CONTRACT、ALGORITHMS、ACCEPTANCE中相关段落。不要把全部历史聊天复制给模型，也不要一次要求它“把项目全部做完”而不给阶段验收。
