# F07 调度助手面板 —— 验收证据

日期：2026-10-10（英国时间 18:40）。执行者：前端/智能体线（Claude Code）。

## 实现
- `frontend/src/protocol/agent.ts`：AGENT_CONTRACT v0.1 的 zod schema（health / explain / interpret / compare）。
- `frontend/src/lib/agentApi.ts`、`useAssistant.ts`：`/agent/*` 客户端与状态机；启动时探测 `/agent/health`，面板标题显示「模型 deepseek-chat / 模板模式 / 离线」。
- `frontend/src/components/AssistantPanel.tsx`：三块。
  1. 解释：总览 / 未配送 / 本车 / 装卸作业单四个按钮，可附一句提问；输出带「模型 or 模板」徽标与「已核对 N 个数字」。
  2. 指令：输入一句话 → `interpret` → `patchDescribe.ts` 把 RFC 6902 补丁翻成「门店 S01 · 最早收货 08:20 → 09:30」式的字段级 diff，列出未采纳操作与理由 → 「确认并重新求解」或「放弃」。未确认不提交任何求解。
  3. 对比：确认后 App 记下基线（当前请求 + 响应），把 patched_request 走既有 `useSolver` 提交；新结果到达后自动调用 `compare`，表格显示调整前后的门店、车辆、费用、里程、利用率、准时率，徽标标明「费用可比 / 不可比」，不可比时不显示百分比。
- 助手服务不可达时面板显示离线提示，其余功能不受影响；求解服务不可达时「确认并重新求解」禁用。
- 新一次求解开始时清空旧方案的解释，避免旧解释冒充新方案。

## 实际运行（真实求解器 + 真实 DeepSeek）
脚本 `_tools/shot_flow.mjs`（headless Chrome）对 `service:small-11` 执行：

3. 输入「V02 今天不出车」→ 解析为「车辆 V02：可用 → 移除」，摘要「移除车辆 V02。」。截图 `F07_3-interpreted.png`、`F07_3-interpreted_panel.png`。
4. 点「确认并重新求解」→ 页面案例变为「已导入：调整后：small-11」，新 run_id 66459279…；结果到达后自动对比：10 → 10 店，4 → 3 辆，1,577.1 → 1,270.7 元，538.6 → 435.4 km，费用可比，变化 −19.4%；模型叙述先讲覆盖不变再讲费用，已核对 11 个数字。截图 `F07_4-compared.png`、`F07_4-compared_panel.png`。
浏览器控制台无错误。`npm run build` 通过。

模板模式（无密钥）验收：停掉密钥后 health 返回 `configured=false`，面板标「模板模式」，同一流程可走通（A01–A04 测试与 `artifacts/evidence/A01.md` 中的模板输出覆盖此路径）。

## 限制
- 对比只在确认补丁后自动触发；手动选两个历史方案对比未做。
- 指令为单轮；没有对话记忆。
- 对比表只显示 6 项常用指标，完整 12 项在响应 `deltas` 中。
