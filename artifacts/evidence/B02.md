## 完成标准核对

- [x] 示例均可解析：request-success、request-partial → SolveRequest；response-success/partial/failed → JobResponse
- [x] 每类非法输入有明确字段错误：重复 ID、未知 store_id、负/零尺寸、NaN/Infinity、反向时间窗、非法 method、time_limit/max_iterations 超范围、无箱门店、空 stores/vehicles/boxes、错误 schema_version
- [x] 不得静默修正未知门店：`box.store_id` 不在 stores 集合时直接抛错，不做任何修正
- [x] 有效边界不误拒绝：0 坐标、0 费用、默认 options、小数重量

## 实现要点

- 字段级约束用 pydantic `Field(gt=0/ge=0/le=1440/allow_inf_nan=False)` + `Literal` 落实，错误 `loc` 自动指向具体字段。
- 跨字段约束（重复 ID、未知门店引用、每店至少一箱、时间窗颠倒）用 `model_validator(mode="after")`，错误消息写明具体 ID/门店。
- 尺寸用 `int`（整数 mm），重量/费用/时间/坐标用 `float`（允许小数），与 CONTRACT.md D02 一致。
- 响应模型（JobResponse 等）与三份 response 样例逐字段对齐，保留 `is_mock`、`termination_reason`、`error` 等语义。

## 限制与说明

- HTTP 422 错误外壳（`{schema_version, error:{code:"INVALID_INPUT", message, details}}`）由 B13 的 API 层组装，本卡只保证 pydantic 层抛出 `ValidationError`。
- `details[].path` 的 JSON Pointer 精确拼接在 B13 处理 FastAPI `RequestValidationError` 时完成。
